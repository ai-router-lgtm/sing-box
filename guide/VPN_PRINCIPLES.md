## 网络拓扑与 VPN 原理

### 普通网络访问（无 VPN）

```
┌──────────────┐
│  客户端设备   │
│ (你的电脑)    │
└──────┬───────┘
       │ 请求
       ↓
┌──────────────┐
│  ISP DNS/GW  │ ← 可以看到你访问的所有网站
│  (运营商网关)  │
└──────┬───────┘
       │
       ↓
    互联网
       ↓
┌──────────────┐
│  目标网站     │
│ (Google等)    │  ← 看到你的真实IP
└──────────────┘
```

**问题**：
- ❌ ISP 能看到你访问的所有域名（DNS 污染）
- ❌ 网站能看到你的真实 IP
- ❌ 某些网站在你的国家被阻止

### 使用 Sing-Box 的网络访问（代理模式）

```
┌──────────────┐
│  客户端应用   │
│ (Chrome等)    │
└──────┬───────┘
       │ http://google.com:80
       │ (纯文本，未加密)
       ↓
┌──────────────────────────┐
│  Sing-Box (客户端)         │  ← 你的本地代理服务
│  ├─ Inbound:           │     监听 127.0.0.1:1080
│  │  接收应用的请求      │
│  ├─ 路由判断            │     判断是否需要走 VPN
│  ├─ DNS 解析            │     防止 DNS 污染
│  └─ Outbound:          │     连接到 VPN 服务器
│     发送加密请求        │
└──────┬──────────────────┘
       │ 加密流量
       │ (TLS/QUIC)
       ↓
    ┌─ VPN 传输 ─┐
    │ (Internet) │
    └────────────┘
       ↓
┌──────────────────────────┐
│  Sing-Box (服务器端)       │
│  ├─ Inbound:           │
│  │  接收加密连接        │
│  ├─ TLS 解密            │
│  └─ Outbound:          │
│     以 VPN 服务器IP     │
│     发送到目标         │
└──────┬──────────────────┘
       │ 代理请求
       ↓
┌──────────────┐
│  目标网站     │
│ (Google等)    │  ← 看到的是 VPN 服务器 IP
└──────────────┘
```

**优点**：
- ✅ ISP 只能看到加密流量，看不到具体访问的网站
- ✅ 网站看到的是 VPN 服务器的 IP，而不是你的真实 IP
- ✅ 可以访问被地区限制的内容

## Sing-Box 在 VPN 中的角色

### 从功能角度看

| 功能模块 | Sing-Box 中的组件 | VPN 中的作用 |
|---------|------------------|------------|
| **协议支持** | Inbound/Outbound | 支持多种 VPN/代理协议 |
| **流量分类** | Route（路由表） | 判断流量应该走 VPN 还是直连 |
| **DNS 处理** | DNS 模块 | 防止 DNS 污染，支持 DNS 分流 |
| **加密传输** | TLS/QUIC | 保护数据，确保隐私 |
| **连接管理** | TCP/UDP 连接池 | 多连接复用，提升性能 |

### 从数据流角度看

```
应用层：
Chrome → socks5://127.0.0.1:1080

传输层：
┌─────────────┐
│ Inbound     │ ← 接收来自应用的请求
│ (mixed)     │
└┬────────────┘
 │
 │ 路由引擎判断：
 │ - 是国内吗？→ 直连
 │ - 是国外吗？→ VPN
 │
 ├─→ Route ──→ Direct Outbound → 直接连接目标
 │
 └─→ Route ──→ VLESS/Trojan Outbound → 连接 VPN 服务器

VPN 层：
加密协议（VLESS/Trojan/Hysteria2）
↓
TLS/QUIC 加密
↓
网络层（Internet）

目标层：
最终到达目标服务器
```

## 流量分析

### 案例 1：访问 Google（国外网站）

```
1. 应用请求
   Chrome: GET https://google.com

2. Sing-Box 接收（Inbound）
   [mixed] 127.0.0.1:1080 收到请求

3. DNS 解析（防污染）
   google.com → 查询 8.8.8.8（通过 VPN）
   返回真实 IP

4. 路由判断（Route）
   IP 属地：美国？ → geoip: us
   域名：google.com？ → domain: google.com
   结论：走 VPN

5. 出站连接（Outbound）
   vless-out 连接 vpn.example.com:443
   加密发送 Google 的请求

6. VPN 服务器解密
   收到加密数据，解密为原始请求

7. 转发请求
   从 VPN 服务器 IP 向 Google 发起请求
   Google 返回响应

8. 返回给客户端
   加密响应 → 本地 Sing-Box 解密 → Chrome 渲染
```

**时间线**：
```
Chrome ─(纯文本)→ Sing-Box ─(加密)→ VPN ─(明文)→ Google
 0ms          1-2ms        50-100ms        1-5ms
```

### 案例 2：访问 Bilibili（国内网站）

```
1. 应用请求
   Chrome: GET https://bilibili.com

2. Sing-Box 接收（Inbound）
   [mixed] 127.0.0.1:1080 收到请求

3. DNS 解析
   bilibili.com → 查询本地 DNS
   返回国内 CDN IP

4. 路由判断（Route）
   Domain Suffix: .com？ → 检查 GeoSite
   geosite: cn ✓

5. 出站连接（Outbound）
   direct-out 直接连接 Bilibili
   不经过 VPN

6. 直连获取
   从本地 IP 向 Bilibili 发起请求
   获得最近的 CDN 节点内容

7. 返回给客户端
   Bilibili 响应 → Sing-Box → Chrome 渲染
```

**优点**：
- 快速（无 VPN 开销）
- 支持本地 ISP 优化
- 获得更好的内容地域化

## 关键概念速览

### 什么是代理（Proxy）?

```
代理 = 中间人
- 客户端把请求发给代理
- 代理代表你向服务器发起请求
- 服务器只看到代理，看不到你
```

### 什么是加密（Encryption）?

```
加密 = 把明文包装成密文
- 中间路径中任何人都看不懂
- 只有有密钥的人才能解密
- Sing-Box 用 TLS/QUIC 加密代理连接
```

### 什么是分流（Split Tunnel）?

```
分流 = 不是所有流量都走代理
- 国内流量：直接连接（快速）
- 国外流量：代理连接（有隐私）
- Sing-Box Route 实现分流
```

### 什么是 FakeIP?

```
FakeIP = 本地生成的虚拟 IP
- DNS 查询返回本地生成的 IP
- 数据包到达时再转向真实 IP
- 加快 DNS 分流，提升性能
```

### Sing-Box 的安全保障

| 安全层面 | 保障措施 |
|---------|--------|
| **传输层** | TLS 1.3、QUIC、Trojan 等加密协议 |

## 常见误区纠正

### ❌ 误区 1：使用 VPN 后网速会变慢 50%

**真相**：
- ✅ 好的 VPN 只增加 5-20% 延迟
- ✅ Sing-Box 的分流模式国内流量几乎无损
- ✅ 性能取决于 VPN 服务器位置和连接质量

### ❌ 误区 2：VPN 可以完全隐藏身份

**真相**：
- ✅ VPN 隐藏 IP，但不隐藏 ISP 连接
- ✅ 网站可以通过其他方式追踪你（cookies、指纹识别）
- ✅ VPN 是隐私工具，不是匿名工具

### ❌ 误区 3：加密等于安全

**真相**：
- ✅ VPN 只保护传输过程，不保护数据本身
- ✅ 弱密码、未更新的密钥都是风险
- ✅ 安全是多层防护的结配
